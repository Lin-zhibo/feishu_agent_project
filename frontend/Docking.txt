前端这边已经改成真实接口模式了，需要后端开放一个接口，前端会按下面这个格式请求。

接口地址：

POST http://localhost:8000/api/run


请求头：


Content-Type: application/json


前端发送的数据：

{
  "input": "用户在前端输入的需求文本"
}


后端返回格式固定成下面这样：


{
  "success": true,
  "message": "运行成功",
  "stages": {
    "requirements": "需求分析阶段输出",
    "solution": "方案设计阶段输出",
    "code_gen": "代码生成阶段输出",
    "test_gen": "测试生成阶段输出",
    "review": "代码审查阶段输出",
    "delivery": "交付集成阶段输出"
  },
  "final_output": "最终汇总结果"
}


如果运行失败，返回：


{
  "success": false,
  "message": "错误原因",
  "stages": {
    "requirements": "",
    "solution": "",
    "code_gen": "",
    "test_gen": "",
    "review": "",
    "delivery": ""
  },
  "final_output": ""
}


另外因为我前端本地运行在：


http://localhost:5173


所以后端需要配置跨域，允许 http://localhost:5173 访问后端接口。

目前还没有流式返回。也就是前端点按钮后，后端跑完整个 pipeline，再一次性把六个阶段结果返回给前端。

另外我这块字段名已经写死了，所以 stages 里面这六个 key 最好就别动了：requirements、solution、code_gen、test_gen、review、delivery。
