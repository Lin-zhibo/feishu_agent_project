## 1. 功能需求（Functional Requirements）

### FR-1：小程序端获取临时登录凭证（code）

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-1.1 | 用户点击「微信登录」按钮时，小程序调用 `wx.login()` 接口获取临时登录凭证 `code` | 高 |
| FR-1.2 | 系统应判断当前网络状态，若网络不可用则给出友好提示，不发起登录请求 | 高 |
| FR-1.3 | 若 `wx.login()` 调用失败（如返回 errMsg 非 success），系统应向用户展示错误提示并允许重试 | 高 |
| FR-1.4 | 系统应在调用 `wx.login()` 前检查 `code` 的时效性，避免重复使用过期 code | 中 |

### FR-2：前端向后端发送登录请求

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-2.1 | 小程序前端将获取到的 `code` 通过 HTTPS 请求发送至开发者自有后端服务器 | 高 |
| FR-2.2 | 请求应包含必要参数：`code`（必填）、`appId`（可选，用于多租户场景） | 高 |
| FR-2.3 | 前端应在请求中附加设备信息和用户代理（User-Agent），用于安全审计 | 低 |

### FR-3：后端服务端与微信服务器交互

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-3.1 | 后端收到 `code` 后，调用微信接口 `https://api.weixin.qq.com/sns/jscode2session`，传入参数 `appid`、`secret`、`js_code`、`grant_type=authorization_code` | 高 |
| FR-3.2 | 后端应使用 HTTPS 协议进行通信，接口超时时间设置为 ≤ 5 秒 | 高 |
| FR-3.3 | 后端需对微信返回的 `session_key` 和 `openid` 进行非空校验 | 高 |
| FR-3.4 | 后端需校验微信返回的 `errcode`，若为非零值（如 -1、40029、45011 等），应记录日志并返回友好的错误码给前端 | 高 |

### FR-4：用户信息绑定与会话管理

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-4.1 | 后端根据 `openid` 在用户表中查询或创建用户记录（首次登录自动注册） | 高 |
| FR-4.2 | 后端生成自定义登录态令牌（如 JWT Token 或 Session ID），有效期建议为 7 天 | 高 |
| FR-4.3 | 后端将 `session_key` 加密存储，用于后续数据解密（如获取手机号、用户信息），不应明文保存 | 高 |
| FR-4.4 | 后端将生成的 Token 和用户基本信息（如 openid、unionid）返回给小程序前端 | 高 |

### FR-5：前端处理登录成功响应

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-5.1 | 小程序前端接收后端返回的 Token 并存入 `wx.setStorageSync('token', token)` | 高 |
| FR-5.2 | 前端在后续 API 请求的 HTTP Header 中携带该 Token（格式：`Authorization: Bearer <token>`） | 高 |
| FR-5.3 | 登录成功后，前端应跳转至首页或用户指定的目标页面 | 中 |

### FR-6：用户信息获取（可选增强）

| 编号 | 需求描述 | 优先级 |
|------|----------|--------|
| FR-6.1 | （可选）在登录后，通过 `wx.getUserProfile` 获取用户头像、昵称等公开信息 | 中 |
| FR-6.2 | （可选）使用 `wx.getPhoneNumber` 结合 `session_key` 解密获取用户手机号 | 低 |
| FR-6.3 | 用户信息展示前应获得用户明确授权，遵循《微信小程序用户隐私保护指引》 | 高 |

## 2. 非功能需求（Non-Functional Requirements）

### NFR-1：安全性

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| NFR-1.1 | 所有涉及 `code`、`session_key`、`openid` 的传输必须使用 HTTPS 加密 | 无明文传输，抓包不可见敏感数据 |
| NFR-1.2 | `secret`（微信小程序密钥）不得出现在前端代码或客户端存储中 | 静态代码扫描通过 |
| NFR-1.3 | Token 应使用强随机数算法生成（如 HMAC-SHA256），且不可被伪造 | 通过安全测试 |
| NFR-1.4 | 单个 `code` 只能被使用一次，重复使用应返回错误 | 后端有幂等性校验逻辑 |
| NFR-1.5 | 登录接口应有频率限制，同一 IP 或同一设备每分钟不超过 60 次 | 压测通过 |

### NFR-2：性能

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| NFR-2.1 | 从用户点击登录到登录成功的全链路耗时 ≤ 2 秒（不含用户授权弹窗等待） | TP95 < 2s |
| NFR-2.2 | 后端与微信服务器通信的接口超时设置为 ≤ 5 秒 | 超时触发熔断 |
| NFR-2.3 | 系统应支持并发登录请求 ≥ 1000 QPS | 压测通过 |

### NFR-3：可靠性

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| NFR-3.1 | 微信接口调用失败时应有自动重试机制（最多重试 2 次，指数退避） | 日志验证 |
| NFR-3.2 | 登录服务应保证 ≥ 99.9% 可用性 | 监控数据 |
| NFR-3.3 | Token 过期后，系统应能通过刷新机制（如 refresh token）自动续期 | 功能测试通过 |

### NFR-4：可维护性

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| NFR-4.1 | 登录流程的关键节点（`wx.login`、后端收 code、jscode2session、Token 签发）应有完善的日志记录 | 日志可追溯全链路 |
| NFR-4.2 | 日志中不得记录 `session_key` 明文和 `secret` | 日志审计通过 |
| NFR-4.3 | 登录模块代码应有单元测试覆盖，覆盖率 ≥ 80% | JaCoCo / Karma 报告 |

### NFR-5：兼容性

| 编号 | 需求描述 | 验收标准 |
|------|----------|----------|
| NFR-5.1 | 支持微信基础库版本 ≥ 2.10.0 | 测试通过 |
| NFR-5.2 | 兼容 iOS 和 Android 两端微信客户端 | 双端回归测试通过 |

## 3. 验收标准（Acceptance Criteria）

### AC-1：核心登录流程验收

```
场景：用户首次使用微信小程序并点击「微信登录」
Given  用户已安装微信客户端且网络正常
When   用户点击「微信登录」按钮
Then   小程序调用 wx.login() 获取 code
    And 前端将 code 发送至后端登录接口
    And 后端调用微信 jscode2session 接口
    And 后端创建用户记录并生成 Token
    And 前端收到 Token 并存入本地缓存
    And 页面跳转至首页
```

### AC-2：已有用户登录验收

```
场景：老用户再次登录
Given  用户已注册且本地缓存有有效 Token
When   用户进入小程序
Then   系统自动使用缓存 Token 尝试静默登录
    And 若 Token 有效，直接进入首页（无感登录）
    And 若 Token 过期，跳转至登录页提示用户重新登录
```

### AC-3：异常处理验收

```
场景 A：wx.login() 调用失败
When   wx.login() 返回错误
Then   前端显示"登录失败，请检查网络后重试"提示
    And 提供「重新登录」按钮

场景 B：code 已过期或无效
When   后端收到无效 code 并调用 jscode2session 返回 errcode=40029
Then   后端返回错误码 TOKEN_EXPIRED
    And 前端重新调用 wx.login() 获取新 code

场景 C：网络超时
When   后端调用微信接口超时（>5s）
Then   后端返回错误码 NETWORK_TIMEOUT
    And 前端提示"网络繁忙，请稍后再试"

场景 D：后端服务不可用
When   后端服务返回 5xx 错误
Then   前端提示"服务维护中，请稍后再试"
    And 不能暴露服务器内部错误信息
```

### AC-4：安全验收

| 编号 | 验收项 | 通过标准 |
|------|--------|----------|
| AC-4.1 | 抓包验证所有接口使用 HTTPS | 无 HTTP 明文请求 |
| AC-4.2 | 扫描前端代码不应出现 appSecret | 扫描报告通过 |
| AC-4.3 | 重放攻击测试：同一 code 重复请求 | 第二次返回 400 |
| AC-4.4 | Token 伪造测试：篡改 Token 内容 | 服务端校验失败返回 401 |

### AC-5：兼容性验收

| 编号 | 设备/环境 | 预期结果 |
|------|-----------|----------|
| AC-5.1 | iPhone 12 / iOS 16 / 微信 8.0+ | 登录流程正常 |
| AC-5.2 | Xiaomi 14 / Android 14 / 微信 8.0+ | 登录流程正常 |
| AC-5.3 | 微信开发者工具 / 基础库 2.10.0 | 登录流程正常 |
| AC-5.4 | 弱网环境（模拟 3G / 丢包 10%） | 超时后正确提示 |

## 附录 A：接口定义速查

### A.1 小程序前端 → 后端

```
POST /api/auth/wechat-login
Content-Type: application/json

Request Body:
{
  "code": "临时登录凭证",
  "deviceInfo": "可选设备信息"
}

Response (200):
{
  "code": 0,
  "data": {
    "token": "自定义登录令牌",
    "expiresIn": 604800,
    "user": {
      "openId": "微信开放ID",
      "avatarUrl": "可选",
      "nickName": "可选"
    }
  }
}
```

### A.2 后端 → 微信服务器

```
GET https://api.weixin.qq.com/sns/jscode2session
    ?appid=APPID
    &secret=SECRET
    &js_code=JSCODE
    &grant_type=authorization_code

Response:
{
  "openid": "xxxxxx",
  "session_key": "xxxxxx",
  "unionid": "xxxxxx",  // 可选，需绑定开放平台
  "errcode": 0,
  "errmsg": ""
}
```
