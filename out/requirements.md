# 开源PC端记账软件 — 结构化需求文档

**版本**: 1.0  
**作者**: 需求分析团队  
**日期**: 2025年  

---

## 一、产品概述

### 1.1 产品愿景
打造一款**免费、开源、跨平台**的PC端个人/家庭记账软件，聚焦简洁易用的日常收支管理，同时提供专业级的报表分析能力，成为个人财务管理的首选工具。

### 1.2 目标用户
| 用户角色 | 描述 |
|---------|------|
| **个人用户** | 有日常记账习惯的上班族、学生，关注收支流水和月度分析 |
| **家庭用户** | 管理家庭共同开支的用户，需多成员协作（可选） |
| **自由职业者** | 需简单记录项目收入和开支，生成基础财务报表 |

### 1.3 核心设计理念
- **隐私优先**：数据默认本地存储，不强制联网
- **离线可用**：核心功能完全离线运行
- **简洁直观**：三分钟上手，无需会计知识
- **开放可扩展**：支持插件/脚本扩展、数据完全可导出

---

## 二、技术架构决策

| 决策项 | 选择 | 理由 |
|-------|------|------|
| **操作系统** | Windows 10+ / macOS 11+ / Linux (主流发行版) | 覆盖绝大多数PC用户 |
| **技术栈** | Tauri 2.0 + Rust (后端) + TypeScript + React (前端) | 性能优异、体积小、安全、跨平台 |
| **数据库** | SQLite (通过 `rusqlite`) | 零配置、嵌入式、本地优先 |
| **UI框架** | React + Tailwind CSS + Radix UI | 现代化、可访问性好 |
| **图表库** | ECharts / Apache ECharts | 丰富图表类型、中文支持好 |
| **国际化** | i18next + react-i18next | 成熟、生态丰富 |
| **开源协议** | MIT | 最宽松，鼓励社区贡献和商业使用 |
| **构建工具** | Vite + esbuild | 极速开发体验 |

| NFR-1.5 | 报表生成 | 常规月度报表生成 ≤ 0.5 秒 |

## 五、验收标准 (Acceptance Criteria)

### AC-1: 核心记账流程

```
场景: 用户记录一笔日常支出
前提: 用户已创建账本且至少有一个支出账户和一个支出分类
步骤:
  1. 用户点击"新建交易"按钮或按下 Ctrl+N
  2. 系统弹出记账弹窗
  3. 用户选择类型: 支出
  4. 用户输入金额: 35.00
  5. 用户选择分类: 餐饮 → 午餐
  6. 用户选择账户: 微信零钱
  7. 用户输入备注: "公司楼下兰州拉面"
  8. 用户点击"保存"
结果:
  ✓ 交易列表中出现该条记录
  ✓ 微信零钱账户余额减少 35.00
  ✓ 当月餐饮分类支出增加 35.00
  ✓ 仪表盘本月支出总额增加 35.00
  ✓ 操作耗时 < 10 秒（含用户输入时间）
```

### AC-2: 月度报表生成

```
场景: 用户查看上个月的财务报表
前提: 账本中至少包含 30 天以上的交易数据
步骤:
  1. 用户导航到"报表"页面
  2. 选择时间范围: 上个月
  3. 点击"生成报表"
结果:
  ✓ 3 秒内展示报表
  ✓ 报表包含: 总收入、总支出、结余
  ✓ 支出分类饼图正确反映各分类占比
  ✓ 每日支出趋势折线图正确
  ✓ 各账户期末余额正确
  ✓ 支持导出为 PDF/Excel
```

### AC-3: 跨平台运行

```
场景: 用户在不同操作系统上使用软件
前提: 同一账本文件
测试平台:
  - Windows 11
  - macOS 14 (Sonoma)
  - Ubuntu 22.04 (X11/Wayland)
结果:
  ✓ 三种平台安装包体积均 ≤ 30MB
  ✓ 核心功能（记账、查看、搜索）在三种平台上完全一致
  ✓ UI 布局在不同分辨率（1366×768 至 4K）下正常显示
  ✓ 中文/英文输入在三种平台均正常
  ✓ 数据库文件可在三种平台间互换使用
```

### AC-4: 数据安全与备份

```
场景: 用户需要保障数据安全
测试:
  1. 用户为账本设置密码加密
     → 不输入密码无法打开账本
     → 输入错误密码提示错误
  2. 用户连续记账 7 天
     → "备份目录"中存在最近 7 天的自动备份文件
  3. 用户手动点击"备份"
     → 生成时间戳命名的完整备份文件（.db 或 .zip）
  4. 用户删除一条交易后恢复
     → 从备份文件恢复，数据完整
  5. 模拟应用崩溃（强制关闭进程）
     → 重新启动后，已保存的最后一条交易未丢失
```

### AC-5: 性能基准

```
场景: 软件在旧硬件上运行仍有良好体验
硬件: 4GB RAM, Intel i5-7200U, SATA SSD
测试数据: 5 万条随机交易记录
验收:
  ✓ 应用启动 ≤ 2.5 秒
  ✓ 交易列表滚动流畅（60fps）
  ✓ 全文搜索 ≤ 1 秒
  ✓ 年度报表生成 ≤ 2 秒
  ✓ 内存峰值 ≤ 250MB
```

### AC-6: 国际化

```
场景: 非中文用户使用软件
测试:
  1. 用户在设置中将语言切换到 English
     → 所有界面文本切换为英文
     → 日期格式变为 MM/dd/yyyy
     → 货币符号保持用户设置（默认 $）
  2. 用户录入中文备注
     → 保存和检索正常
  3. 中文用户使用中文界面
     → 所有界面文本为简体中文
     → 日期格式为 yyyy-MM-dd
     → 货币符号为 ¥
```
